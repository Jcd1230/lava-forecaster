# Lightspeed Antigen & Vaccine Assessment (LAVA) Forecaster

This repository is the **Lightspeed Antigen & Vaccine Assessment (LAVA) Forecaster**, a high-performance, ICE-compatible immunization evaluation and forecasting engine. It serves as a fast, drop-in replacement for the **Immunization Calculation Engine (ICE)** and implements the CDC Clinical Decision Support for Immunization (CDSi) rules using a type-safe, compile-time Domain Specific Language (DSL) in Rust.

By compile-time pre-compilation of rules, schema-free internal representations, and memory-efficient static data structures, the LAVA Forecaster achieves sub-millisecond latencies and high throughput suited for real-time and bulk processing workloads.

## Getting Started

### Prerequisites
Make sure you have Rust and Cargo installed (recommended: Rust 1.80+ or edition 2024).

### Building the Project
To compile the project and all binaries in release mode:
```bash
cargo build --release
```

### Running the REST Server
The Axum-based server listens on port `8081` by default and exposes endpoints for single, bulk, and FlatBuffer requests:
```bash
cargo run --release -- --server
```

**Exposed Endpoints:**
* `POST /evaluate` (or `/opencds-decision-support-service/api/resources/evaluate`): Processes a single patient request in either legacy JSON or simplified JSON formats.
* `POST /evaluate_bulk`: Processes a JSON array of patient requests in parallel using Rayon.
* `POST /evaluate_bulk_flatbuffers`: Processes a binary stream of FlatBuffer requests for maximum throughput.

### Evaluating a Request File
You can evaluate a local JSON request file directly without running the server:
```bash
cargo run --release -- <path_to_request.json>
```

## Testing & Verification

Verification matches Rust evaluation and forecasting logic against the Java ICE reference implementation.

### 1. Running the Rust-Native Test Runner
The local Rust-native runner executes test cases stored in `tests/cases/` and compares results against expected snapshots:
```bash
cargo run --release --bin test_runner -- --run tests/cases
```
Options:
* `--group <GROUP>`: Filter by vaccine group name (e.g., `POLIO` or `DTP`).
* `--case <CASE_NAME>`: Run a specific test case by name.

### 1a. Running CDC Compliance Against the CDSi CSV Export
The runner can also execute the Rust forecaster directly against the expected evaluation and forecast fields from the CDSi CSV export:
```bash
cargo run --release --bin test_runner -- --run-cdc-csv ../cdsi-healthy-childhood-and-adult-test-cases.csv
```
Options:
* `--group <GROUP>`: Filter by internal vaccine group name (e.g., `POLIO` or `DTP`).
* `--case <CASE_NAME_OR_TEST_ID>`: Run a specific CDC case by normalized case name or raw `CDC_Test_ID`.
* `--rest-url <RUST_URL>`: Query a running Rust server instead of executing in-process.
* `--verbose`, `-v`: Show detailed CDC side-by-side evaluation and forecast comparisons.

### 2. Generating Snapshots from Java ICE
If Java reference snapshots are missing or need updating, run:
```bash
cargo run --release --bin test_runner -- --record tests/cases [http://localhost:8080]
```
*(Requires the Java ICE server to be running).*

### 3. Using `mise` Commands (Workspace-wide)
From the project root, a set of convenience scripts are available via `mise`:
* `mise run test`: Runs the Rust-native verification runner.
* `mise run test-group -- <group>`: Runs verification for a single vaccine group.
* `mise run test-compare -- --group <group>`: Directly runs differential testing between live Java and LAVA Forecaster.

## Benchmarking

A benchmarking tool is included to measure evaluation throughput and latency across loaded test cases:
```bash
cargo run --release --bin benchmark -- tests/cases
```

It provides:
1. **Full Suite Throughput**: Microseconds per patient evaluation and total patient evaluations per second.
2. **Complex Case Latency**: Average evaluation latency for the patient history with the most doses.
3. **Minimal Case Latency**: Average evaluation latency for a newborn case with no dose history.

## Compile-Time DSL Architecture

Vaccine schedules are written using a declarative builder pattern. This avoids runtime configuration parsing and keeps evaluation loops allocation-free.

### Example Schedule (`schedules.rs`)
```rust
use lava_cvx_macro::cvx;
use crate::schedule::CompiledSeries;

pub fn varicella_2_dose_series() -> CompiledSeries {
    let allowed_cvx = &[cvx!("21"), cvx!("94")]; // Varicella, MMRV

    CompiledSeries::builder("VARICELLA_2_DOSE_SERIES")
        .code("VARICELLA_2_DOSE_SERIES")
        .vaccine_group("VARICELLA")
        .num_doses(2)
        .dose(1, |d| d
            .abs_min_age("1y-4d")
            .min_age("1y")
            .earliest_recommended_age("1y")
            .cvx(allowed_cvx)
        )
        .dose(2, |d| d
            .abs_min_age("13m")
            .min_age("15m")
            .earliest_recommended_interval("84d")
            .cvx(allowed_cvx)
        )
        .interval(1, 2, |i| i
            .abs_min_interval("28d")
            .min_interval("84d")
        )
        .build()
}
```

### Overrides Registry
For logic that deviates from standard parameters, individual vaccine modules use closure hooks in `overrides.rs`:
* **Evaluation Overrides**: Modify validity or reasons for a dose dynamically (e.g. live-virus intervals).
* **Forecast Overrides**: Exclude patients based on birth year, or conditionally complete vaccine series (e.g. HepB adult rules).
* **Series Switches**: Dynamically change target series based on vaccines received.
